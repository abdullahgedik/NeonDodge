# Neon Dodge — Project Notes

A LÖVE2D (Lua) project the user is building specifically **to learn LÖVE and Lua**. Not a shipping product — every feature is chosen for what it teaches, so lean toward explaining/using idiomatic LÖVE patterns over the fastest hack. This file exists because the coding session this project was being developed in was rooted in an unrelated repo (`kensan_app`, a Flutter project) and couldn't be switched — start fresh sessions with this file's directory (`NeonDodge/`) as the actual working directory/root so tools resolve paths correctly.

**Claude Code sessions do not sync across the user's machines** (confirmed — session history is local/per-install, not account-synced even in the desktop app). This file is the actual continuity mechanism between machines/sessions: keep it current. See the last working agreement below.

## What the game is

Top-down dodge/collect arcade game, 800x600 window, no resize.
- Player: cyan square. Move with WASD/arrows or a gamepad's left stick/d-pad. Shift or gamepad A dashes (0.1s burst, 0.75s cooldown, both tunable by cards) — **the player is a true phase-through while dashing**, not just damage-immune: every hazard's collision check (Enemy, ZigzagEnemy, Boss body, Boss laser, Projectile) skips entirely while `player.is_dashing`, so nothing gets destroyed/consumed and no FX/hitstop fires either, on top of `take_damage` itself short-circuiting to `"dodged"` as a defensive fallback. Orb/VoidOrb pickups are deliberately *not* phased — they're beneficial, so dashing through them still collects them. This is what makes the Quick Dash/Long Dash cards genuinely defensive tools, not just mobility.
- HP: 3 max by default, shown as hearts top-left. Max HP can change at runtime via cards (Vitality +1, Glass Cannon -1).
- Red triangles ("Enemy") fall from top → touching one costs 1 HP. Speed ramps +5 per miss, capped (`Enemy.max_speed`) so it can't run away unbounded.
- Orange/red-ish diamond ("ZigzagEnemy") — same damage rule and capped ramp as Enemy, but sine-waves horizontally while falling. Fill `(1, 0.4, 0.05)` with a dark red `(0.7, 0, 0)` outline for readability against the yellow orb.
- Yellow circles ("Orb") → +5 score. Every 5th orb: heals +1 HP if not at max HP, otherwise **grants a one-hit shield instead** (only if not already shielded). The "Orbs: X/5" HUD counter shows progress toward that next milestone (wraps every 5, showing 5/5 right at the trigger moment), not the lifetime total.
- Purple orbs ("VoidOrb") → +10 score on catch; **missing** one costs 1 HP (unless the Void Ward card is active); its fall speed is eased by the same "Slow Fall" card modifier as Enemy/ZigzagEnemy, since missing one has a real HP cost like touching a hazard does (Orb, a pure pickup with no downside, is deliberately not affected).
- Bronze/copper octagon ("Mine") — a genuinely different kind of hazard: the body itself is harmless, only its shockwave deals damage. Falls slowly, anchors in place at a random height, then arms: a growing warning ring appears at its blast radius immediately (so there's maximal time to route around it), and its core flashes hotter orange-red and faster as the ~1.3s telegraph runs out. On detonation, only a player still inside the blast radius (dash phase-through still applies) takes 1 HP, boss-tier shake (0.2/8, bigger than a normal hazard touch); the mine is removed either way. "Dodge the moving shape" vs. "be clear of this zone by the deadline" — the first hazard in the game that isn't a contact-on-touch threat.
- Shield: one-hit block, blue ring wrapping the player, quick pop-in animation then holds fixed size/alpha (no continuous pulsing).
- Boss: spawns every 6th wave (`BOSS_WAVE_INTERVAL` in `main.lua`), ~14s encounter then leaves on its own (game is pure-dodge, no player attack, so every boss is a survive-the-encounter set piece, not a fight). Touching a boss body costs 1 HP, gated by a hit-cooldown so overlap doesn't melt HP every frame. Surviving it awards bonus score and opens the card-select screen. Three deliberate breathers pace these transitions instead of snapping straight through them: a **"BOSS INCOMING" telegraph** (`BOSS_INCOMING_DELAY`, 1.6s — existing hazards keep falling but no new ones spawn, and a pulsing warning shows) before the boss actually appears; a **freeze-frame beat** (`POST_BOSS_PAUSE_DURATION`, 1.0s — the whole game visibly holds still) after the boss dies and before the card screen opens; and a **confirm hold** (`CARD_CONFIRM_DELAY`, 0.4s — the picked card stays highlighted, the other two dim) after choosing a card and before play actually resumes. **Nine distinct boss types cycle in a fixed escalating sequence** (`Boss.SEQUENCE` in `src/boss.lua`: sentinel → charger → homing → bomber → laser → phantom → splitter → warden → turret → repeats). The four newer types are deliberately *interleaved* rather than appended — tacked onto the end they'd sit behind five encounters (wave 36+) and effectively never be seen in a normal run:
  - **Sentinel** patrols horizontally (full screen width, see below) + fires a 7-shot downward spread. Multiple attempts were made to stop players camping above it: a fixed upward fan (blocked by corners), then a shot tracking the player's real position (still trivially dodgeable as a single periodic projectile from a static spot) — both were dropped in favor of denying the position outright: it's bigger-bodied (90x60 → 125x75) and walls off the top of the screen entirely for the duration of the encounter (`Player.min_y`, drawn as a faint dashed line) so "stand above the boss" isn't a legal position at all.
  - **Homing** patrols slower and fires rare projectiles that curve toward the player (steering/vector-math exercise); homing shots expire after 6s (with a small green burst FX) so they can't chase forever once the encounter's over. Any still-active homing shots are also explosion-cleared the instant the boss itself starts leaving, so its threat doesn't outlive it even within that 6s window. Also enforces the same `Player.min_y` top-of-screen wall as Sentinel/Splitter — its own shots steer continuously so coverage was never the issue, but a player parked far enough above still had time to read and juke each shot before it curved into range.
  - **Laser** barely moves but its beam does: a full-width **or** full-height band that sweeps edge-to-edge across the *entire* screen, randomly one of left→right / right→left / top→bottom / bottom→top each cycle (cooldown → telegraph → firing). Telegraph shows a single line at the start position only (an end-line too was tried and dropped — with a full edge-to-edge sweep the far end is always a screen edge, so showing it added confusion, not clarity). The encounter tracks completed sweeps directly (`laser_sweep_count`) and exits only once exactly 4 have finished, instead of sharing the generic per-type time budget — that budget didn't line up with the beam's own cycle length, so the boss could leave mid-telegraph or cut the last sweep off partway through. Also fires a straight (non-homing) aimed shot at the player on its own independent ~1s cadence, decoupled from the beam cycle so shots don't wait on it — this is the one place `fire_aimed_shot` is still used; Sentinel/Splitter's own aimed "guard" shots were removed once the `Player.min_y` wall made them redundant.
  - **Splitter** is small/fast and splits into two smaller independent clones partway through its encounter (8-shot spread original, clones a bit weaker at 6) — the original (65x45 → 85x55) also enforces the same top-of-screen `Player.min_y` wall as Sentinel for its whole encounter (clones keep their smaller size but still enforce the wall, at a slightly lower line matching their shorter body). The original patrols the *full* screen width now — its `patrol_amplitude` used to fall well short of actually reaching the screen edges from its spawn point, leaving a permanently-unvisited strip on both sides. The clones don't sine-patrol at all: they ping-pong in a straight line at a fixed speed, reversing off the screen edges *and* off each other (`is_bouncer`/`bounce_dir`/`bounce_speed`, resolved each frame by `resolve_bouncer_collisions`) — sine-patrolling both off a shared formula made them drift side-by-side in near lockstep instead of splitting up to cover the arena, and giving that sine a wide-enough amplitude to reach both edges from any split position also made them absurdly fast.
  - **Turret** orbits in a circle around a fixed arena point (not stationary) and fires full-circle projectile rings that rotate their angle offset a little more each burst (a slow bullet-hell spiral) — each volley is actually **two** rings back to back, ~0.18s apart, the second interleaved exactly into the first's gaps (offset by half the ring's angular spacing), so dodging one ring's pattern isn't enough.
  - **Charger** is the only boss that fires *nothing* — its body is the entire attack. It tracks the player's column at a capped speed (closing the gap, never teleporting onto them), stops dead, telegraphs the full-height column it's about to fall through, then slams to the floor and climbs back up. Standing still is the failure state, and dash phase-through is the clean answer, which makes it the sharpest test of the dash in the game. Enforces `Player.min_y` (175) — it only ever slams *downward*, so anything above its hover line is a position it structurally cannot threaten.
  - **Bomber** seeds the arena with real `Mine` hazards instead of shooting (via a `spawn_mine` callback into `main.lua` → `Mine.spawn_at`), so its bombs telegraph, explode and damage through the exact same path a wave-spawned mine does — boss-scale zone denial in a visual language the player already knows. One bomb per volley is dropped on the player's current position (punishing camping), the other scattered (keeping the whole arena live). Also enforces `Player.min_y` (130), since bombs can't be seeded at the very top without overlapping the boss's own body.
  - **Warden** squeezes the legal play area itself: a slow ease-out shrink from the full screen down to a centered 380px-wide arena whose top edge sits at y=215, reached over 80% of the encounter and held there. Generalizes the existing one-edge `Player.min_y` wall into all four edges. Its actual shots (a slow 5-wide spread) barely matter — the threat is that the room to dodge them keeps shrinking.
  - **Phantom** has no readable patrol at all: it holds position ~1.5s, fades out, reappears somewhere else in the upper arena, and fires the instant it lands. While anything but fully visible it's `intangible` — collision *and* firing both switch off, since a half-faded boss you can walk into (or that shoots from nowhere) reads as a bug. Blink positions are always ≥150px from the player, so it can't materialize on top of them for an unreactable hit. It fires a **full ring** rather than a downward fan precisely because its position is unpredictable — a directional attack would be dodgeable by standing above wherever it happened to land, and the ring is what lets it skip the `player_min_y` wall every other top-threatened type needs.
- Debug spawns any boss on demand, independently of the real in-run sequence: **F3** steps to the next type in `Boss.SEQUENCE`, and **number keys 1-9** jump straight to a specific one (F3 alone meant nine presses to reach the last type, each replacing the previous mid-encounter, which made testing any single boss tedious). The overlay lists the whole roster with its hotkey number and marks which one F3 points at, and each live instance's sub-state shows alongside its enter/hover/exit phase — see `Boss.debug_summary`/`debug_state` below. Adding a boss type needs only `src/boss.lua` (the `BOSS_TYPES` registry plus `Boss.SEQUENCE`); both the wave cadence and every debug hotkey pick it up automatically.
- **Roguelike card system**: after every boss encounter, gameplay pauses and offers 3 of 20 cards (see `src/cards.lua`) — pick via mouse click, number keys 1/2/3, WASD/arrows + Enter/Space, or gamepad d-pad + A. Effects span survivability (+max HP, auto-shield/regen ticking, dodge chance, banked extra-life revives, Void Ward), score (flat bonuses, multipliers, low-HP double-score), mobility (move speed, dash cooldown/duration), and hazard-easing (fall speed, enemy speed-ramp, hitstop/shake intensity).
- Wave-based difficulty: spawn rates ramp over ~2 minutes via `src/difficulty.lua`; `Difficulty.wave()` drives both the boss cadence and the UI wave counter. Waves 1-3 are shorter than the steady-state 20s (10s/13s/16s) so the early game escalates noticeably faster instead of an uneventful sit before anything changes — wave 4 onward is a flat 20s.
- **Hazard storms**: every 3rd wave that *isn't* a boss wave (with `BOSS_WAVE_INTERVAL` a multiple of `STORM_WAVE_INTERVAL`, storms and bosses naturally alternate every 3 waves with no gaps), a ~1.2s telegraph warning plays (gameplay unchanged — the point is "brace yourself", unlike the boss telegraph's "things calm down"), then a 10s storm where one hazard's spawn rate roughly triples, before dropping back to normal. A storm is defined by which single hazard it **narrows down to**, not by piling everything on: every hazard *not* named in that storm type is suppressed outright for its duration. An early version sped up every type at once and was unsurvivable in practice — the fix was narrowing the mix, not tuning the multiplier down.
- **Four storm types**, each built around one hazard and each unlocking alongside it (`STORM_TYPES` in `main.lua`, gated on the same `unlock_stage` as the hazard roster), so the storm variety grows as the game does instead of every storm being the same event forever. Each storm rolls randomly from the types unlocked so far, never repeating the previous one back-to-back when there's a choice. The banner is named and colored by the type itself:
  - **HAZARD STORM** (always available) — Enemy + Orb ~3x. The original: a red-triangle flood with extra orb pickups as the reward for braving it.
  - **VOID RAIN** (with VoidOrb) — a purple downpour that inverts the game's core instinct: these must be *caught*, and missing one costs HP, so "dodge everything" is what kills you.
  - **CROSSFIRE** (with ZigzagEnemy) — weaving hazards only; reading sine paths instead of straight falls.
  - **MINEFIELD** (with Mine) — zone denial rather than dodging; the arena fills with blast circles and it's the safe space that keeps moving, not the hazards.
- **Progressive hazard unlocks**: instead of every hazard/pickup type being live from wave 1 with only their spawn *rate* ramping, the roster itself grows one event at a time. Only Enemy and Orb are ever active from the start; the first boss or storm to conclude unlocks VoidOrb, the second unlocks ZigzagEnemy, the third (and every one after) unlocks Mine. With the current 6/3 boss/storm cadence this lands as: waves 1-3 Enemy+Orb only, VoidOrb after the wave-3 storm, ZigzagEnemy after the wave-6 boss, Mine (full roster) after the wave-9 storm. Each new type's introduction rides on an event milestone that already exists, rather than adding a separate unlock timer.
- Screen-space shaders, always layered: bloom/glow (`src/bloom.lua`) on the whole scene, plus an on-hit chromatic-aberration + vignette pulse and an automatic red "heartbeat" vignette while at 1 HP (`src/hit_effect.lua`).
- Persistent high score via `love.filesystem` (`src/high_score.lua`), shown on the menu and game-over screens. The main menu's "Reset High Score" option won't fire on a single click — it *arms* (button turns red, label changes to "Click again to confirm") and needs a second confirm within 3s, disarming automatically on timeout or on navigating the cursor away, so a misclick can't silently erase the record.
- Debug mode (**F1** to toggle) — bottom-screen overlay of state/wave/boss/player HP/active card modifiers/owned cards. While enabled: **F2** forces a card-select screen, **F3** force-spawns the boss, **F4** skips a full wave forward, **F5** toggles god mode (no damage).
- Game states: `menu` → `playing` → `paused` (P / gamepad Start) → `card_select` (after every boss) → `game_over` (R / gamepad A to restart). From `paused`, R/gamepad A also restarts and M/gamepad B quits straight back to `menu`, both without needing to die first — either path saves the in-progress score as a potential high score before discarding it, same fairness as a normal death.
- **Main menu and pause are real navigable menus**, not just hint text: main menu offers "Start Game"/"Reset High Score"/"Quit", pause offers "Resume"/"Restart"/"Quit to Menu" — both drive-able by mouse click, keyboard (arrows/WASD + Enter/Space), or gamepad (d-pad + A), on top of the direct hotkeys/buttons above which still work unchanged as shortcuts. The cursor always defaults to the option matching the old single-key behavior (main menu → "Start Game", pause → "Resume"), so pressing Space/A with zero navigation reproduces exactly what used to happen.

## Architecture

Module-per-entity pattern in `src/`, each module is a table returned from its file, generally exposing `load/update/draw/pause/resume/reset`. Modules receive sibling modules as parameters where practical (e.g. `Enemy.update(dt, game_over, player, on_collision, spawn_rate)`); a few modules (`Cards`, `Debug`, `FXManager`) are `require`d directly by others since they're read-only "service" lookups rather than entities needing lifecycle wiring — this is an established, intentional exception, not drift to fix. Those direct requires are always **top-level locals** (`local FXManager = require("src/fx_manager")` at the head of the file), never re-required inside a function body — `fx_manager.lua` has no requires of its own, so there's no circular-dependency reason for the inline form.

- `main.lua` — owns score, orb count, screen-shake state, hit-stop timer, wave/boss/card trigger bookkeeping; wires modules together via callback functions passed into each module's `update`. Centralizes card-modifier application for anything that isn't naturally owned by one module (`love.shake`/`love.hitstop` multiply by `shake_mult`/`hitstop_mult`; `love.increase_score` applies `score_mult`/`low_hp_score_mult` and rounds to an integer — a fractional multiplier like Glass Cannon's 1.5x will otherwise leave float scores). Three transition timers pace the normal→boss→card-select→normal flow, all ticked in `love.update`: `boss_incoming_timer` (defers the actual `Boss.spawn` call, suppressing new hazard spawns via `suppress_spawns` in the meantime — existing hazards keep falling, only new spawns stop), `post_boss_pause_timer` (set by `on_boss_encounter_end` instead of calling `trigger_card_select` immediately; ticked with an early `return` right after the `hitstop_timer` check, the same "skip the rest of this frame" trick hitstop already uses, so the whole game visibly freezes for the duration), and `card_confirm_timer` (set by `choose_card` instead of resuming immediately, ticked inside the `CARD_SELECT` branch of `love.update`, calling `finish_card_select()` once it elapses). `trigger_card_select`/`finish_card_select` are **forward-declared** (`local trigger_card_select` etc. near the top of the file, assigned later without the `local` keyword) specifically so `love.update` — defined earlier in the file — can call them; Lua resolves `local` scope by textual position, not call order, so without the forward declaration `love.update` would see them as undefined globals. `trigger_card_select` defensively clears `post_boss_pause_timer`/`pending_card_select` on entry so it can't misbehave if reached a different way (e.g. debug F2) than the delayed path. Storm events (`storm_telegraph_timer`, `storm_timer`) are scheduled the same wave-transition way boss encounters are (`wave > last_storm_wave and wave % STORM_WAVE_INTERVAL == 0`), with an explicit `wave % BOSS_WAVE_INTERVAL ~= 0` guard so a storm can never land on a boss wave — the two systems are otherwise completely independent. All five hazards now resolve their spawn period through one `spawn_rate_for(kind, storm, suppressed, unlocked)` helper instead of five hand-written expressions; it returns `math.huge` ("never spawns") for all three suppression cases — boss encounter on screen, hazard not unlocked yet, or a storm running that this hazard isn't part of — and otherwise scales `Difficulty.spawn_rate(kind)` by the storm's own per-hazard multiplier. `STORM_TYPES` is the storm registry: each entry has an `id`/`name`/`color` (the banner names and colors itself from this), a `required_unlock_stage` keying it to the same counter that gates the hazard roster, and a `rates` table of per-hazard multipliers. Because those rates multiply a *period*, a value below 1 means "more often" (0.35 ≈ 3x) and 1 means "unchanged" — and any hazard **not listed is suppressed outright**, which is what makes a storm a narrowing rather than a pile-on. `pick_storm_type()` rolls from the unlocked types excluding the previous one (falling back to a repeat only when that leaves nothing, i.e. early on when swarm is the whole roster). `storm_type` is chosen at *telegraph* time, not when the storm starts, so the warning banner can name what's coming; spawn rates only actually change once `storm_timer > 0`. `src/difficulty.lua` itself is untouched either way — the ramp stays the ramp, storms are a `main.lua`-level event layered on top. A single `unlock_stage` counter (0-3, `UNLOCK_STAGE_VOID_ORB`/`_ZIGZAG`/`_MINE` mark the thresholds) gates whether VoidOrb/ZigzagEnemy/Mine are even eligible to spawn at all — each is forced to `math.huge` alongside the existing `suppress_spawns`/`storm_active` checks until `unlock_stage` reaches its threshold. It's incremented by exactly 1 (capped at `MAX_UNLOCK_STAGE`) from two places: `love.on_boss_encounter_end` and the `storm_timer` tick block the instant it crosses back to 0 — i.e. once an event *concludes*, not when it starts, matching "unlock the next thing after that boss/storm" rather than "at the start of it." `restart_game(target_state)` takes an optional target (defaults to `PLAYING`) so `quit_to_menu()` can reuse the exact same reset logic but land on `MENU` instead — it also unconditionally calls `HighScore.try_save(score)` and `love.resume()` before wiping state, neither of which the original GAME_OVER-only restart path needed (death already saves the score, and GAME_OVER was never reached via `love.pause()`), but both are required once restart/quit became reachable *from* `PAUSED`: skipping the resume would leave every module's `is_paused` flag stuck true, silently freezing the "fresh" run. `menu_cursor` is a single shared cursor variable for whichever simple menu (main menu or pause) is currently showing — only one is ever active at once, so one variable covers both; `toggle_pause`/`quit_to_menu` reset it to 1 on entry so a stale index from the *other* menu (which may have more or fewer options) can never carry over. `select_main_menu_option(index)`/`select_pause_menu_option(index)` are the dispatch tables mapping a menu index to an action, called from keyboard (arrows/WASD + Enter/Space), gamepad (d-pad + A), and mouse (`love.mousepressed`'s shared local `hit_index(x, y, rects)` helper, reused for card-select too) alike — every input path funnels through the same two functions so there's exactly one place each menu's behavior is defined. `reset_confirm_timer` (ticked only while `GameState.MENU`) implements the "Reset High Score" arm/confirm: `select_main_menu_option(2)` starts the timer on a first select and only calls `HighScore.reset()` if it's already running (a second select within the window); it's zeroed on timeout, on navigating `menu_cursor` away from `MAIN_MENU_RESET_INDEX`, and on leaving the menu via `quit_to_menu`, so it can never persist stale across screens. Three small pieces of shared plumbing keep the file's repeated shapes from drifting apart: `PAUSABLE_MODULES` (the one list `love.pause()`/`love.resume()` both iterate, instead of two hand-maintained 10-call blocks — deliberately *not* every module, since Background/FXManager keep animating while paused and Bloom/HitEffect/UI/HighScore have no such state, and deliberately separate from `restart_game`'s reset list, which covers a different set); `hazard_collision_handler(module, shake_duration, shake_magnitude)`, a factory building the five `love.on_*_player_collision` handlers (Enemy/ZigzagEnemy/Projectile share the regular hazard shake, Mine/Boss the heavier one, and Boss passes `nil` for the module since it has nothing to remove) — they were five hand-copied bodies of the same remove → `is_dead`/`GAME_OVER` guard → `apply_player_hit` sequence, which is exactly how the void-orb-miss handler once silently lost its flicker and death guard; and `step_cursor(cursor, delta, count)`, the single wraparound-arithmetic helper behind `move_main_menu_cursor`/`move_pause_menu_cursor`/`move_card_cursor`, which had been spelled out inline at all six keyboard/gamepad navigation sites.
- `src/game_state.lua` — explicit state machine: `GameState.MENU/PLAYING/PAUSED/CARD_SELECT/GAME_OVER`, `.set()`/`.is()`. Single source of truth for game state — don't reintroduce parallel booleans or per-module mirrors of the same flag.
- `src/pool.lua` — generic object pool (`Pool.new(factory)`, `:spawn(init)`, `:release(index)`, `:clear()`). O(1) swap-and-pop removal, **safe specifically because callers iterate backward** (`for i = #active, 1, -1`) and only ever release at the *current* loop index. Re-verify that invariant before reusing this pattern for a differently-iterated entity type.
- `src/player.lua`, `src/enemy.lua`, `src/zigzag_enemy.lua`, `src/mine.lua`, `src/orb.lua`, `src/void_orb.lua`, `src/projectile.lua` — entity modules. `src/mine.lua` breaks from the rest of the pattern in one respect: its collision check only ever fires once, in a single frame (the instant `arm_timer >= TELEGRAPH_DURATION`), rather than every frame like a contact hazard — no `hit_cooldown` needed, since there's no lingering-overlap case to guard against. It removes itself directly (`Mine.remove(i)`) when the player was clear of the blast, but — matching every other hazard's convention — leaves removal to the caller (`Xxx.remove(index)` inside the `on_collision` handler in `main.lua`) when it did hit, so the object isn't double-released. `Player.take_damage` returns one of `"damaged"/"dead"/"shielded"/"dodged"/"revived"` and callers (`main.lua`) branch on all five; the dash i-frame check and Debug god-mode both also short-circuit straight to `"dodged"`, before shield/dodge-chance/extra-life are even consulted, so dashing/god-mode never burns those resources. Dash invincibility is enforced at **two layers**: `player.is_dashing` gates collision detection itself in every hazard module (true phase-through, no FX/removal), and `take_damage`'s own check is a defensive fallback in case something ever calls it anyway. `Projectile.spawn(x, y, dir_x, dir_y, homing)` — the optional `homing` flag makes a projectile steer its direction toward the player each frame at a clamped turn rate (`steer_towards` local fn, itself built on a hand-written `atan2` from single-arg `math.atan` — `math.atan2` runs fine on LÖVE's LuaJIT but is removed in standard Lua 5.3+ and it's unclear whether the two-arg `math.atan(y,x)` form is safe to assume, so this sidesteps the question entirely) instead of flying straight, and gives it a finite `homing_lifetime` (6s, small green burst FX on expiry) so it can't chase forever; non-homing projectiles still just rely on leaving the screen bounds to get cleaned up. `Projectile.clear_homing()` explosion-clears every active homing shot at once (used when the homing boss leaves — see `boss.lua`'s `on_type_exit`). Homing projectiles render green regardless of who fired them. `Player.min_x/min_y/max_x/max_y` are the rect `Player.bounds()` clamps into, replacing the hardcoded screen edges entirely (`Player.reset_bounds()` restores the full screen, called from both `load` and `reset`). `main.lua` is the only writer — it assigns all four from `Boss.get_player_bounds()` every frame — so Player itself doesn't know or care *why* a wall exists. `Player.draw_walls()` draws a faint dashed line along each edge that's actually been pushed in from the screen edge, so a restriction is always visible rather than an invisible wall the player discovers by bumping into it. This started as a single `Player.min_y` scalar for the anti-top-camping wall and was generalized to all four edges for the Warden boss. `Mine.spawn_at(x, y)` drops a mine that's already anchored and arming at an exact spot (clamped on-screen), skipping the falling phase — used by the Bomber boss, which places its bombs deliberately rather than letting them rain from the top; everything after that point (telegraph, blast, damage) is the normal mine path.
- `src/boss.lua` — extension points worth knowing before adding a type: **`movement`** (a function `(instance, type_def, dt, player)` owning where the boss is each hover frame — defaults to the shared sine `patrol_movement`; `orbit_movement`/`bounce_movement`/`charge_movement`/`blink_movement` are the others. This replaced an `if is_orbiter / elseif is_bouncer / else` chain that stopped scaling at four modes; the flags themselves survive because *spawn placement*, the edge clamp and clone-vs-clone collision key off them, which isn't movement); **`fire`** (optional — Charger has none, since its body is the attack — receiving `(instance, type_def, spawn_projectile, player, spawn_mine)`); **`draw_extra(instance, type_def)`** (per-type overlay, each type deciding for itself whether its current phase warrants drawing anything — the laser beam and charger's warning column both go through it); **`player_min_y`** and the warden's `arena_*` instance fields (both feeding `Boss.get_player_bounds`); and two generic per-instance flags, **`alpha`** (draw opacity, phantom-only) and **`intangible`** (switches off collision *and* firing in one go — used by the phantom mid-blink, where either half alone would read as a bug). **Multi-instance**, not a true singleton: `Boss.instances` is a small array (almost always length 1, briefly 2 after a Splitter split), iterated backward like the pool convention (`for i = #active, 1, -1`, remove-at-current-index only) so mid-loop splits/removals are safe. `Boss.active` is a plain boolean kept in sync (true on spawn, false the instant the instance list empties) — every other module still just reads it as before. Per-type behavior lives in a `BOSS_TYPES` registry (`id -> {width, height, colors, patrol_amplitude/speed OR is_orbiter+orbit_radius/orbit_center_y/speed, fire fn, optional fire_second fn, optional player_min_y}`); shared code (enter/exit movement, the sine-patrol horizontal movement — `patrol_amplitude = 0` gives "stationary" for free — AABB collision, rounded-rect draw) lives once in the module and reads whichever type's config applies. `patrol_amplitude` for every sine-patrol type must be large enough to actually reach both screen edges from its spawn `base_x` (a centered `base_x` needs `amplitude >= half the screen minus half the boss width`) — Sentinel/Splitter both originally fell well short of this, leaving a permanently-unvisited strip on both sides of the screen no matter what else patched the top-camping exploit; values were corrected once this was noticed. `splitter_clone` doesn't use the sine patrol at all (`is_bouncer = true`): it moves in a straight line at a constant `bounce_speed`, reversing `bounce_dir` off the screen edges (in the same clamp block that would otherwise just stop a sine-patrol type) and off the other clone via the module-level `resolve_bouncer_collisions(instances)` helper (called once per frame from `Boss.update`, after both instances have moved) — sine-patrolling clones off a shared formula with only a small spawn-offset between them made them drift side-by-side in near lockstep, and giving that sine enough amplitude to reach either edge from an arbitrary split position also made them absurdly fast (amplitude directly scales peak velocity). The collision check pushes both clones' directions explicitly *away* from each other (not a toggle) whenever their bounding boxes overlap, so re-triggering every frame while still overlapping can't cause flip-flip jitter — it just keeps asserting "apart" until they've actually separated. `fire_aimed_shot` is a single shot computed once toward the player's *current* position at fire time (not steering afterward, unlike homing) — closes any geometric gap a fixed angle/fan can't (corners included). Laser still uses it for its independent aimed shot. Sentinel/Splitter/splitter_clone used it too for a time (a `guard_interval`/`guard_fire` hook, added specifically to fight top-camping) but that was removed once `Player.min_y` made it redundant — denying the position outright beats out-tracking a player already standing in it. All hazard collision checks (`check_instance_collision`, `check_laser_collision`) skip entirely while `player.is_dashing`. A generic `instance.pending_second_burst` countdown (ticked in `update_instance` right after the normal fire step, harmless/no-op for any type that doesn't set it) calls `type_def.fire_second` once it elapses — Turret is currently the only type using it, firing a second ring ~0.18s after the first at a half-step rotation offset so the two rings interleave into one denser lattice instead of one being simply a delayed repeat. `is_orbiter` (Turret) branches to circular motion around a fixed arena point instead of the sine patrol — **`Boss.spawn` and the enter-phase target Y both special-case orbiters to land exactly at the orbit formula's angle-0 position**, otherwise hover starts with an instant jump from the generic entry point to wherever the orbit math first evaluates to (this bit us once already — same class of bug as the original patrol "zip," same fix: make the starting reference match). Laser's beam is its own self-contained sub-system (`laser_state`: cooldown → telegraph → firing) drawn as a **full-width or full-height band that sweeps edge-to-edge across the entire screen** (`laser_axis` picks horizontal/vertical, `laser_row_start`/`laser_row_end` are the two screen edges in the direction chosen, interpolated into `laser_row_y` during firing) — earlier versions used a fixed pivot, then a small-range slide, and both still left some region of the arena permanently safe; a full edge-to-edge sweep across a randomized axis/direction doesn't. Laser's aimed projectile shot (via the shared `fire_aimed_shot` helper) runs on its own independent timer (`shot_timer`/`LASER_SHOT_INTERVAL`), decoupled from the beam's cooldown/telegraph/firing cycle so it can fire more often than the beam cycles. Laser's exit condition is **shot-count-based, not time-based**: `instance.laser_sweep_count` increments each time a firing phase completes, and the type branches to check that against `LASER_MAX_SWEEPS` instead of the shared `hover_timer >= ENCOUNTER_DURATION` every other type uses — the two budgets didn't line up, so the boss could previously exit mid-telegraph or truncate the last sweep. `Boss.update`/`update_instance` take an optional `on_type_exit(type_id)` callback, fired once exactly when an instance's phase flips to `"exit"` — `main.lua` uses it to call `Projectile.clear_homing()` specifically when the leaving type is `"homing"`, but the hook itself is generic (any type could react to its own exit this way, not just Homing). `Boss.debug_summary()` returns a one-line `"type:phase/detail, type:phase/detail"` string for the debug overlay, where `detail` comes from an optional per-type **`debug_state(instance)`** — the generic `phase` sits at `"hover"` for an entire encounter, so it hides the sub-state machine most types actually run on (set for `laser` (beam state + sweep count, since sweeps are its real exit condition), `charger`, `phantom` (including whether it's currently `intangible`) and `warden` (its live arena size, hover-only and rounded, since a stale exit-phase value would describe a wall that's no longer enforced)). `Boss.get_player_bounds()` returns the rect the player is confined to this frame as `min_x, min_y, max_x, max_y` — the full screen unless a live encounter narrows it. Two kinds of restriction feed in: the opt-in per-type `type_def.player_min_y` (set on `sentinel`/`homing`/`splitter`/`splitter_clone`/`charger`/`bomber`, walling off the top of the screen so they can't be camped above) and the warden's per-instance `arena_min_x`/`arena_max_x`/`arena_min_y` (written each frame by `update_warden_arena`, shrinking all the way in over its encounter). It only counts instances in `"hover"` — during enter/exit the boss isn't threatening that space yet/anymore — and combines multiple instances to the **tightest of each edge** rather than first-wins. `main.lua` writes all four straight into `Player` every frame, so restrictions turn on/off automatically as encounters start and end, and Player itself never knows why.

- `src/background.lua` — parallax starfield.
- `src/ui.lua` — HUD + menu/pause/game-over/card-select overlay text, driven by `GameState.current`. `UI.card_layout()` is the single source of truth for the 3 card rectangles, shared with `main.lua`'s mouse-click hit-testing so visuals and click boxes can't drift — the card-select appear animation (below) is purely a *draw-time* transform layered on top of those same rects via `love.graphics.push/translate/scale/pop`, so it can never desync from the click boxes. `UI.draw_card_select(cards, cursor_index, elapsed, chosen_index)` eases each card in (85%→100% scale, small rise, fade-in) over `CARD_ANIM_DURATION`, staggered `CARD_STAGGER` seconds apart per card index for a left-to-right cascade; when `chosen_index` is set (during `main.lua`'s post-pick confirm delay) the chosen card gets a gold highlight and the other two dim to 35% alpha instead of animating further. Deliberately simpler than the card-select treatment (no appear animation, no stagger) since picking a card is the core roguelike decision and these are just navigation. `UI.draw_simple_menu` takes an optional `danger_index` — the one button it renders in a red warning color/border regardless of hover state, used by the main menu's armed "Reset High Score" (relabeled to "Click again to confirm" while armed, both computed in `UI.draw_menu` from a `reset_armed` flag `main.lua` passes in).
- `src/difficulty.lua` — wave counter + spawn-rate lerp. `Difficulty.wave()` and `Difficulty.skip_wave()` both go through a shared local `wave_at(elapsed)` helper (returns the wave number plus that wave's `[start, end)` boundary) so the two can't drift out of sync — `wave()` just reads the number, `skip_wave()` (the debug hotkey) jumps `elapsed` precisely to the next wave's boundary regardless of how far into the current wave it was. `EARLY_WAVE_DURATIONS` gives waves 1-3 a shorter length than the steady-state `WAVE_DURATION`; `RAMP_WAVES` (used only in `spawn_rate`) is a fixed real-time budget (`RAMP_WAVES * WAVE_DURATION` seconds) for the density ramp, deliberately decoupled from wave *number* so shortening early waves doesn't also warp how fast spawn rates ramp.
- `src/bloom.lua` — render scene to a canvas, bright-pass threshold + separable gaussian blur, additive composite into `Bloom.final_canvas`. **The threshold shader uses max-channel brightness, not perceptual luminance** — perceptual weights (favoring green) unfairly discount saturated reds/blues/purples, so a fully-lit red or purple shape would never bloom under the "correct-looking" luma formula. Keep this in mind when picking colors for new entities (e.g. future boss variants) if you want them to glow.
- `src/hit_effect.lua` — post-processes `Bloom.final_canvas` before it hits the screen: `hit_strength` (decaying, triggered on damage) drives chromatic aberration + vignette; `danger_strength` (continuous, driven by `Player.lives == 1`) drives an independent red-tint pulse. Two separate uniforms so the two effects can stack without fighting.
- `src/high_score.lua` — `love.filesystem` read/write, simple "only overwrite if higher" save. `HighScore.reset()` writes `0` straight to the save file and `HighScore.value`, no confirmation logic in this module — that lives entirely in `main.lua`/`src/ui.lua` (see the reset-confirm-arm note below), keeping this module a plain dumb read/write/reset API.
- `src/cards.lua` — the roguelike layer. `CARD_POOL` (20 defs: `id/name/description/max_stacks/on_pick/modifiers`), `Cards.owned` (stack counts), `Cards.modifiers` (flat table, **fully recomputed from `owned` on every pick** — declarative, not incrementally mutated). `Cards.get(key, default)` is the read API every other module uses. Two cards (Guardian Aura, Regeneration) tick continuously via `Cards.update` and "bank" their trigger — if the condition (shieldless / missing HP) isn't met when the timer completes, it holds at cap and fires the instant the condition becomes true, rather than needing exact timing.
- `src/debug.lua` — F1-toggle overlay + hotkeys; reads `Cards.modifiers`/`Cards.owned` directly for the readout. Owns the boss-spawn cycling state (`Debug.next_boss_index`, `Debug.cycle_boss(sequence)` for F3 and `Debug.select_boss(index, sequence)` for the 1-9 keys — both take the roster as a parameter rather than requiring `Boss`, and `select_boss` returns nil for any non-index so `main.lua` can fall through to whatever else that key does). Deliberately *not* reset by `restart_game`: it's testing state, not run state. `Debug.draw` also takes `unlock_stage`/`max_unlock_stage` from `main.lua` (shown as "Unlock stage: X/3" on the state line) purely for visibility while testing the progressive hazard-unlock system — everything else it reads it pulls straight from the modules it already required.

No assets/sprites/audio — everything is drawn procedurally. User explicitly doesn't want music.

(6) The debug overlay's card/modifier summary iterated via `pairs()`, whose order is unspecified in Lua, so the line could visibly reorder between runs — now sorts keys first.
28. **Transition pacing + card-select animation**: playtesting found the normal→boss, boss→card-select, and card-select→normal transitions all snapped instantly with zero breathing room. Added three timers in `main.lua`, all ticked in `love.update`: `boss_incoming_timer` (1.6s telegraph — a pulsing "BOSS INCOMING" banner shows, new hazard spawns are suppressed via `suppress_spawns`, but already-falling ones keep going, so it reads as "things calm down" rather than a hard freeze) before `Boss.spawn` actually fires; `post_boss_pause_timer` (1.0s full freeze, reusing the exact "early `return` skips the rest of this frame" trick `hitstop_timer` already used, just longer) between the boss dying and the card screen opening; `card_confirm_timer` (0.4s) between picking a card and `finish_card_select()` actually resuming play. `trigger_card_select`/`finish_card_select` had to become forward-declared locals so `love.update` (defined earlier in the file) can call them — Lua scopes `local`s by where they appear in the source, not by call order. Also added a cascading scale/fade-in animation to the card-select screen itself (`src/ui.lua`'s `UI.draw_card_select`, staggered per card, layered as a draw-time transform on top of `UI.card_layout()`'s unchanged rects so it can't desync from the click boxes) and a gold-highlight/dim-others treatment while a pick is being confirmed.
29. **New hazard: telegraphed Mine** (`src/mine.lua`) — a deliberately different kind of threat from anything else in the game: the body itself is harmless, only its shockwave deals damage. Falls slowly, anchors at a random height, then arms — a warning ring at its blast radius appears immediately (full telegraph time to route around it) and its bronze core flashes hotter and faster as the ~1.3s countdown runs out. Detonation only damages a player still inside the radius (dash phase-through applies same as every other hazard); the mine removes itself either way. Wired into the normal spawn-rate system (`src/difficulty.lua`'s `mine` config) and suppressed the same way as every other hazard during boss encounters/telegraphs.
30. **Mid-wave hazard storms**: adds rhythm to the wave system beyond its smooth difficulty ramp. Every 2nd wave that isn't also a boss wave, a brief telegraph plays (gameplay unaffected — deliberately the opposite feel from the boss telegraph's spawn-suppression), then a 10s window where Enemy/ZigzagEnemy/Mine spawn ~3x more often via a plain multiplier on their `Difficulty.spawn_rate(...)` call, scheduled the same wave-transition way boss encounters are and explicitly guarded against ever landing on a boss wave. `src/difficulty.lua` itself is untouched — the ramp stays the ramp, storms are a `main.lua`-level event layered on top.
31. **Storms were unsurvivable — narrowed the hazard mix**: speeding up Enemy, ZigzagEnemy, *and* Mine simultaneously stacked every hazard type's density at once, which playtesting immediately confirmed as "hell of a mayhem, almost impossible to live." Fixed not by tuning the multiplier down, but by narrowing what a storm actually *is*: Enemy and Orb both get the 3x rate boost (a red-triangle swarm with more yellow-orb pickups as the reward for braving it), while ZigzagEnemy/Mine/VoidOrb are suppressed entirely for the storm's duration (spawn rate forced to `math.huge`, the same technique `suppress_spawns` already used for boss encounters) instead of also being sped up.
32. **Fixed player draw order**: the Mine's large, opaque, lingering-in-place body made it obvious that overlapping hazards were rendering *on top of* the player — because `Player.draw()` was called first in `love.draw()`, every entity drawn after it (Enemy, ZigzagEnemy, Mine, Orb, VoidOrb, Boss, Projectile) painted over it whenever they overlapped. This wasn't Mine-specific, just most visible there; `Player.draw()` now runs last, after every other entity, so the player is always visually on top regardless of what it's overlapping.
33. **Slowed the boss/storm cadence and bumped the mine's blast radius**: `BOSS_WAVE_INTERVAL` 3→6, `STORM_WAVE_INTERVAL` 2→3 — since 6 is a multiple of 3, storms and bosses now alternate cleanly every 3 waves with no gaps and no collisions, instead of occasionally landing on the same wave. Also bumped Mine's `BLAST_RADIUS` 70→90.
34. **Progressive hazard unlocks**: previously every hazard/pickup type was live from wave 1, with only the spawn *rate* ramping over time — variety and pace were conflated into one axis. Added `unlock_stage` (0-3) so the roster itself grows one event at a time instead: only Enemy/Orb from the start, then VoidOrb/ZigzagEnemy/Mine each wait for their own threshold, incremented once per boss defeated or storm survived (checked at the moment each concludes, not when it starts). Reuses the exact `math.huge`-spawn-rate suppression technique `suppress_spawns`/`storm_active` already used, just gated by a new condition rather than a new mechanism. Added an "Unlock stage: X/3" readout to the debug overlay for visibility while testing this.
35. **Graduated early wave durations**: the user's real ask, after a round of miscommunication (first read as "score needed to complete a wave," which doesn't exist — waves are pure time), was "the early game feels boring, waves should complete faster there." A flat `WAVE_DURATION` cut would've sped up the *whole* run, not specifically the early game, so instead waves 1-3 got their own shorter lengths (10s/13s/16s vs. the steady 20s from wave 4 on) via a new `EARLY_WAVE_DURATIONS` table. `Difficulty.wave()` and `Difficulty.skip_wave()` were rewritten around a shared `wave_at(elapsed)` helper so both stay in sync. Since boss/storm cadence is wave-*number*-gated, this has the nice side effect of pulling the first storm and first boss noticeably earlier in real time too (first storm ~t=23s instead of ~t=60s, first boss ~t=79s instead of ~t=120s) without touching the density ramp's own timing (`RAMP_WAVES * WAVE_DURATION` stays a fixed 120-second real-time budget, deliberately decoupled from wave number).
36. **Pause menu QoL**: pause previously only supported resuming (P). Added restart (R / gamepad A, same key as the existing game-over restart) and quit-to-menu (M / gamepad B) directly from `PAUSED`, both routed through `restart_game(target_state)` — a small refactor giving that function an optional target state (defaults to `PLAYING`) so `quit_to_menu()` can reuse its exact reset logic but land on `MENU` instead. Surfaced a real latent bug in the process: `restart_game` never called `love.resume()`, which was harmless when it could only ever run from `GAME_OVER` (never paused in the first place) but would have silently frozen every module (`is_paused` stuck true forever) the instant restart/quit became reachable from `PAUSED`. Also made both paths call `HighScore.try_save(score)` before wiping the run, so abandoning a good run via the new options doesn't lose it the way only dying used to preserve it.
37. **Real navigable menus for main menu + pause**: the previous round added restart/quit-to-menu but only as bare hotkeys with hint text. Built a small shared widget instead (`UI.simple_menu_layout`/`UI.draw_simple_menu` in `src/ui.lua`) — a vertical button list usable by mouse click, keyboard, or gamepad — and used it for both screens (main menu: "Start Game"/"Quit"; pause: "Resume"/"Restart"/"Quit to Menu"). Deliberately not given the card-select treatment (no appear animation/stagger) since these are plain navigation, not the core roguelike decision point. All three input methods funnel through two dispatch functions (`select_main_menu_option`/`select_pause_menu_option`), and a single shared `menu_cursor` (reset to 1 whenever either screen is entered, since only one is ever showing at a time) drives the highlight — defaulting to the option matching the old single-key behavior, so pressing Space/A with no navigation still does exactly what it used to. The old direct hotkeys (Space, P/R/M, gamepad a/start/b) all still work unchanged as shortcuts on top of the new menu, not replaced by it.
38. **Reset High Score, with a confirm-arm safety net**: added `HighScore.reset()` (plain zero-and-save) and a 3rd main-menu option. Rather than firing immediately on select — a real risk now that it sits in a click/gamepad-navigable list right next to "Start Game" — it *arms* instead: first select starts `reset_confirm_timer` (3s) and the button re-labels to "Click again to confirm" in a red warning color (`UI.draw_simple_menu`'s new `danger_index` param); only a second select while that timer is still running actually resets it. The timer is zeroed on timeout, on navigating the cursor away from that option, or on leaving the menu entirely, so it can never linger armed across an unrelated screen visit.

39. **Cleanup / modularity pass** (no behavior change — the user asked for this before starting the next feature). Four duplication clusters collapsed: (1) seven entity modules re-`require`d `src/fx_manager` *inside* a function body rather than as a top-level local like they already did for `Cards`/`Debug` — hoisted in all seven (`enemy`, `zigzag_enemy`, `void_orb`, `mine`, `orb`, `projectile`, `boss`; `boss.lua` had three separate inline copies). (2) `love.pause()`/`love.resume()` in `main.lua` were two 10-line blocks calling the same modules in the same order — now one `PAUSABLE_MODULES` list both iterate. (3) The five `love.on_*_player_collision` handlers were hand-copied bodies of one shape — now built by a `hazard_collision_handler` factory, with the two shake tiers as named constants. (4) The menu/card cursor wraparound arithmetic was written out at six separate keyboard/gamepad sites — now one `step_cursor` helper behind three named move functions. Also named two magic numbers that appeared in several places (`MAIN_MENU_RESET_INDEX`, `CARD_CHOICE_COUNT`).

40. **Storm types** (first half of a "keep the game in heat" pass the user asked for): storms were one fixed event forever — Enemy+Orb 3x, every time. Replaced the single `STORM_SPAWN_RATE_MULT` with a `STORM_TYPES` registry of four, each built around one hazard and each gated on the same `unlock_stage` that already gates the hazard roster, so storm variety grows exactly as the hazard roster does (the user's actual framing: "storm types which can happen after a hazard unlocked"). Rolls randomly from what's unlocked, never repeating back-to-back when there's a choice. Also collapsed the five hand-written spawn-rate expressions in `love.update` into one `spawn_rate_for` helper covering all three suppression cases (boss / not-unlocked / not-in-this-storm) — the new per-storm rate table would otherwise have made each of those five expressions worse. The UI's two near-identical storm banner branches became one that names and colors itself from the storm type, and the debug overlay's state line gained a `Storm: id:phase` readout.
41. **Four new boss types** (second half of the same pass), bringing the roster to nine: **Charger** (no projectiles at all — tracks the player's column, telegraphs it, slams to the floor; the body *is* the attack, so standing still is the failure state and dash phase-through is the answer), **Bomber** (seeds real `Mine` hazards via a new `spawn_mine` callback → `Mine.spawn_at`, so its bombs reuse the entire existing telegraph/blast/damage path — one bomb per volley aimed at the player, one scattered), **Warden** (eases the legal play area down to a 380px-wide arena over 80% of the encounter — generalizes `Player.min_y` from one edge to a full rect), and **Phantom** (blinks around the arena, `intangible` while faded so collision *and* firing switch off together, firing a full ring on arrival precisely because its position is unpredictable). Interleaved into `BOSS_SEQUENCE` rather than appended, so they're actually reachable in a normal run. Two refactors were directly required rather than incidental: the movement `if/elseif` chain became a per-type `movement` function (four modes was already the ceiling for a chain, and two of the new types need multi-phase motion), and the laser's special-cased draw became a generic `draw_extra` hook that Charger's warning column also uses. While designing these I caught the same top-camping exploit class documented in items 19-22 in three of the four — Charger only slams downward, Bomber can't seed bombs where its own body is, and Phantom's original downward fan would have been dodgeable from above wherever it landed; the first two got the established `player_min_y` wall, and Phantom was switched to a full ring instead, which fixes it structurally and needs no wall. Verified with a throwaway harness that drove all nine types through full encounters (all reach exit cleanly, leave no instances behind, and produce the attack profile each was designed for) plus the warden's arena floor and `Mine.spawn_at`'s clamping.
42. **Debug readout for the new bosses** (follow-up the user asked for): F3 needed no change — it indexes `BOSS_SEQUENCE`, so extending that list already made all nine cycleable — but the overlay only printed `type:phase`, and `phase` stays `"hover"` for a whole encounter, hiding every sub-state machine (charger's aim/telegraph/slam/retreat, phantom's blink, laser's beam cycle). Added an optional per-type `debug_state(instance)` to the registry, in the same style as `fire`/`movement`/`draw_extra`. Dumping every distinct summary string per encounter then exposed two real bugs in the new code: a 1-frame window where the phantom was drawn fully solid while still `intangible` (so it could be walked through and wasn't firing), and the warden reporting its arena during `exit`, when `update_warden_arena` no longer runs and the bounds aren't enforced — a wall the overlay claimed existed but didn't. Both fixed.
43. **Boss testing was impossible in practice — because the game was being run from the wrong directory.** The user reported still not seeing the new bosses under F3. Root cause wasn't the debug code at all: this session's work lives in a git worktree (`.claude/worktrees/…`) on its own branch, while the main `NeonDodge/` folder is still on `master` with the original five-boss `BOSS_SEQUENCE` — so launching the game the normal way ran none of it. **Worth remembering for any future worktree session: verify which checkout the user actually launches before debugging a "your feature isn't there" report.** Separately, the underlying complaint was fair, so the debug flow was improved anyway: `BOSS_SEQUENCE` moved from `main.lua` to `Boss.SEQUENCE` (it's a property of the boss roster, not of wave scheduling — and it lets `Debug` reach it via the `boss` param it already receives, so adding a type now touches only `src/boss.lua`), F3's cycling counter moved into `Debug` itself, number keys **1-9** were added to spawn a specific boss directly, and the overlay now lists the whole roster with hotkey numbers and a `>` marking F3's next target.
