## What the game is

Top-down dodge/collect arcade game, 800x600 window, no resize.
- Player: cyan square. Move with WASD/arrows or a gamepad's left stick/d-pad. Shift or gamepad A dashes (0.1s burst, 0.75s cooldown, both tunable by cards) — **the player is a true phase-through while dashing**, not just damage-immune: every hazard's collision check (Enemy, ZigzagEnemy, Boss body, Boss laser, Projectile) skips entirely while `player.is_dashing`, so nothing gets destroyed/consumed and no FX/hitstop fires either, on top of `take_damage` itself short-circuiting to `"dodged"` as a defensive fallback. Orb/VoidOrb pickups are deliberately *not* phased — they're beneficial, so dashing through them still collects them. This is what makes the Quick Dash/Long Dash cards genuinely defensive tools, not just mobility.
- HP: 3 max by default, shown as hearts top-left. Max HP can change at runtime via cards (Vitality +1, Glass Cannon -1).
- Red triangles ("Enemy") fall from top → touching one costs 1 HP. Speed ramps +5 per miss, capped (`Enemy.max_speed`) so it can't run away unbounded.
- Orange/red-ish diamond ("ZigzagEnemy") — same damage rule and capped ramp as Enemy, but sine-waves horizontally while falling. Fill `(1, 0.4, 0.05)` with a dark red `(0.7, 0, 0)` outline for readability against the yellow orb.
- Yellow circles ("Orb") → +5 score. Every 5th orb: heals +1 HP if not at max HP, otherwise **grants a one-hit shield instead** (only if not already shielded).
- Purple orbs ("VoidOrb") → +10 score on catch; **missing** one costs 1 HP (unless the Void Ward card is active).
- Shield: one-hit block, blue ring wrapping the player, quick pop-in animation then holds fixed size/alpha (no continuous pulsing).
- Boss: spawns every 3rd wave (`BOSS_WAVE_INTERVAL` in `main.lua`), ~14s encounter then leaves on its own (game is pure-dodge, no player attack, so every boss is a survive-the-encounter set piece, not a fight). Touching a boss body costs 1 HP, gated by a hit-cooldown so overlap doesn't melt HP every frame. Surviving it awards bonus score and opens the card-select screen. **Five distinct boss types cycle in a fixed escalating sequence** (`BOSS_SEQUENCE` in `main.lua`: sentinel → homing → laser → splitter → turret → repeats):
  - **Sentinel** patrols horizontally + fires a 5-shot spread.
  - **Homing** patrols slower and fires rare projectiles that curve toward the player (steering/vector-math exercise); homing shots expire after 6s (with a small green burst FX) so they can't chase forever once the encounter's over. Any still-active homing shots are also explosion-cleared the instant the boss itself starts leaving, so its threat doesn't outlive it even within that 6s window.
  - **Laser** barely moves but its beam does: a full-width **or** full-height band that sweeps edge-to-edge across the *entire* screen, randomly one of left→right / right→left / top→bottom / bottom→top each cycle (cooldown → telegraph → firing). Telegraph shows a single line at the start position only (an end-line too was tried and dropped — with a full edge-to-edge sweep the far end is always a screen edge, so showing it added confusion, not clarity). The encounter tracks completed sweeps directly (`laser_sweep_count`) and exits only once exactly 4 have finished, instead of sharing the generic per-type time budget — that budget didn't line up with the beam's own cycle length, so the boss could leave mid-telegraph or cut the last sweep off partway through. Also fires a straight (non-homing) aimed shot at the player on its own independent ~1s cadence, decoupled from the beam cycle so shots don't wait on it.
  - **Splitter** is small/fast and splits into two smaller independent clones partway through its encounter (6-shot spread each, clones a bit weaker at 4).
  - **Turret** orbits in a circle around a fixed arena point (not stationary) and fires full-circle projectile rings that rotate their angle offset a little more each burst (a slow bullet-hell spiral) — each volley is actually **two** rings back to back, ~0.18s apart, the second interleaved exactly into the first's gaps (offset by half the ring's angular spacing), so dodging one ring's pattern isn't enough.
- Debug's **F3** hotkey cycles through all 5 boss types independently of the real in-run sequence, for fast testing.
- **Roguelike card system**: after every boss encounter, gameplay pauses and offers 3 of 20 cards (see `src/cards.lua`) — pick via mouse click, number keys 1/2/3, WASD/arrows + Enter/Space, or gamepad d-pad + A. Effects span survivability (+max HP, auto-shield/regen ticking, dodge chance, banked extra-life revives, Void Ward), score (flat bonuses, multipliers, low-HP double-score), mobility (move speed, dash cooldown/duration), and hazard-easing (fall speed, enemy speed-ramp, hitstop/shake intensity).
- Wave-based difficulty: spawn rates ramp over ~2 minutes via `src/difficulty.lua`; `Difficulty.wave()` (ticks every 20s) drives both the boss cadence and the UI wave counter.
- Screen-space shaders, always layered: bloom/glow (`src/bloom.lua`) on the whole scene, plus an on-hit chromatic-aberration + vignette pulse and an automatic red "heartbeat" vignette while at 1 HP (`src/hit_effect.lua`).
- Persistent high score via `love.filesystem` (`src/high_score.lua`), shown on the menu and game-over screens.
- Debug mode (**F1** to toggle) — bottom-screen overlay of state/wave/boss/player HP/active card modifiers/owned cards. While enabled: **F2** forces a card-select screen, **F3** force-spawns the boss, **F4** skips a full wave forward, **F5** toggles god mode (no damage).
- Game states: `menu` → `playing` → `paused` (P / gamepad Start) → `card_select` (after every boss) → `game_over` (R / gamepad A to restart).

## Architecture

Module-per-entity pattern in `src/`, each module is a table returned from its file, generally exposing `load/update/draw/pause/resume/reset`. Modules receive sibling modules as parameters where practical (e.g. `Enemy.update(dt, game_over, player, on_collision, spawn_rate)`); a few modules (`Cards`, `Debug`, `FXManager`) are `require`d directly by others since they're read-only "service" lookups rather than entities needing lifecycle wiring — this is an established, intentional exception, not drift to fix.

- `main.lua` — owns score, orb count, screen-shake state, hit-stop timer, wave/boss/card trigger bookkeeping; wires modules together via callback functions passed into each module's `update`. Centralizes card-modifier application for anything that isn't naturally owned by one module (`love.shake`/`love.hitstop` multiply by `shake_mult`/`hitstop_mult`; `love.increase_score` applies `score_mult`/`low_hp_score_mult` and rounds to an integer — a fractional multiplier like Glass Cannon's 1.5x will otherwise leave float scores).
- `src/game_state.lua` — explicit state machine: `GameState.MENU/PLAYING/PAUSED/CARD_SELECT/GAME_OVER`, `.set()`/`.is()`. Single source of truth for game state — don't reintroduce parallel booleans or per-module mirrors of the same flag.
- `src/pool.lua` — generic object pool (`Pool.new(factory)`, `:spawn(init)`, `:release(index)`, `:clear()`). O(1) swap-and-pop removal, **safe specifically because callers iterate backward** (`for i = #active, 1, -1`) and only ever release at the *current* loop index. Re-verify that invariant before reusing this pattern for a differently-iterated entity type.
- `src/player.lua`, `src/enemy.lua`, `src/zigzag_enemy.lua`, `src/orb.lua`, `src/void_orb.lua`, `src/projectile.lua` — entity modules. `Player.take_damage` returns one of `"damaged"/"dead"/"shielded"/"dodged"/"revived"` and callers (`main.lua`) branch on all five; the dash i-frame check and Debug god-mode both also short-circuit straight to `"dodged"`, before shield/dodge-chance/extra-life are even consulted, so dashing/god-mode never burns those resources. Dash invincibility is enforced at **two layers**: `player.is_dashing` gates collision detection itself in every hazard module (true phase-through, no FX/removal), and `take_damage`'s own check is a defensive fallback in case something ever calls it anyway. `Projectile.spawn(x, y, dir_x, dir_y, homing)` — the optional `homing` flag makes a projectile steer its direction toward the player each frame at a clamped turn rate (`steer_towards` local fn, itself built on a hand-written `atan2` from single-arg `math.atan` — `math.atan2` runs fine on LÖVE's LuaJIT but is removed in standard Lua 5.3+ and it's unclear whether the two-arg `math.atan(y,x)` form is safe to assume, so this sidesteps the question entirely) instead of flying straight, and gives it a finite `homing_lifetime` (6s, small green burst FX on expiry) so it can't chase forever; non-homing projectiles still just rely on leaving the screen bounds to get cleaned up. `Projectile.clear_homing()` explosion-clears every active homing shot at once (used when the homing boss leaves — see `boss.lua`'s `on_type_exit`). Homing projectiles render green regardless of who fired them.
- `src/boss.lua` — **multi-instance**, not a true singleton: `Boss.instances` is a small array (almost always length 1, briefly 2 after a Splitter split), iterated backward like the pool convention (`for i = #active, 1, -1`, remove-at-current-index only) so mid-loop splits/removals are safe. `Boss.active` is a plain boolean kept in sync (true on spawn, false the instant the instance list empties) — every other module still just reads it as before. Per-type behavior lives in a `BOSS_TYPES` registry (`id -> {width, height, colors, patrol_amplitude/speed OR is_orbiter+orbit_radius/orbit_center_y/speed, fire fn, optional fire_second fn}`); shared code (enter/exit movement, the sine-patrol horizontal movement — `patrol_amplitude = 0` gives "stationary" for free — AABB collision, rounded-rect draw) lives once in the module and reads whichever type's config applies. All hazard collision checks (`check_instance_collision`, `check_laser_collision`) skip entirely while `player.is_dashing`. A generic `instance.pending_second_burst` countdown (ticked in `update_instance` right after the normal fire step, harmless/no-op for any type that doesn't set it) calls `type_def.fire_second` once it elapses — Turret is currently the only type using it, firing a second ring ~0.18s after the first at a half-step rotation offset so the two rings interleave into one denser lattice instead of one being simply a delayed repeat. `is_orbiter` (Turret) branches to circular motion around a fixed arena point instead of the sine patrol — **`Boss.spawn` and the enter-phase target Y both special-case orbiters to land exactly at the orbit formula's angle-0 position**, otherwise hover starts with an instant jump from the generic entry point to wherever the orbit math first evaluates to (this bit us once already — same class of bug as the original patrol "zip," same fix: make the starting reference match). Laser's beam is its own self-contained sub-system (`laser_state`: cooldown → telegraph → firing) drawn as a **full-width or full-height band that sweeps edge-to-edge across the entire screen** (`laser_axis` picks horizontal/vertical, `laser_row_start`/`laser_row_end` are the two screen edges in the direction chosen, interpolated into `laser_row_y` during firing) — earlier versions used a fixed pivot, then a small-range slide, and both still left some region of the arena permanently safe; a full edge-to-edge sweep across a randomized axis/direction doesn't. Laser's aimed projectile shot runs on its own independent timer (`shot_timer`/`LASER_SHOT_INTERVAL`), decoupled from the beam's cooldown/telegraph/firing cycle so it can fire more often than the beam cycles. Laser's exit condition is **shot-count-based, not time-based**: `instance.laser_sweep_count` increments each time a firing phase completes, and the type branches to check that against `LASER_MAX_SWEEPS` instead of the shared `hover_timer >= ENCOUNTER_DURATION` every other type uses — the two budgets didn't line up, so the boss could previously exit mid-telegraph or truncate the last sweep. `Boss.update`/`update_instance` take an optional `on_type_exit(type_id)` callback, fired once exactly when an instance's phase flips to `"exit"` — `main.lua` uses it to call `Projectile.clear_homing()` specifically when the leaving type is `"homing"`, but the hook itself is generic (any type could react to its own exit this way, not just Homing). `Boss.debug_summary()` returns a one-line `"type:phase, type:phase"` string for the debug overlay.
- `src/fx_manager.lua` — particle-system templates + expanding "ring" shockwave effect (`spawn_ring`). `FXManager.spawn(name, ...)` silently no-ops on an unknown template name.
- `src/background.lua` — parallax starfield.
- `src/ui.lua` — HUD + menu/pause/game-over/card-select overlay text, driven by `GameState.current`. `UI.card_layout()` is the single source of truth for the 3 card rectangles, shared with `main.lua`'s mouse-click hit-testing so visuals and click boxes can't drift.
- `src/difficulty.lua` — wave counter + spawn-rate lerp; `Difficulty.skip_wave()` exists for the debug hotkey.
- `src/bloom.lua` — render scene to a canvas, bright-pass threshold + separable gaussian blur, additive composite into `Bloom.final_canvas`. **The threshold shader uses max-channel brightness, not perceptual luminance** — perceptual weights (favoring green) unfairly discount saturated reds/blues/purples, so a fully-lit red or purple shape would never bloom under the "correct-looking" luma formula. Keep this in mind when picking colors for new entities (e.g. future boss variants) if you want them to glow.
- `src/hit_effect.lua` — post-processes `Bloom.final_canvas` before it hits the screen: `hit_strength` (decaying, triggered on damage) drives chromatic aberration + vignette; `danger_strength` (continuous, driven by `Player.lives == 1`) drives an independent red-tint pulse. Two separate uniforms so the two effects can stack without fighting.
- `src/high_score.lua` — `love.filesystem` read/write, simple "only overwrite if higher" save.
- `src/cards.lua` — the roguelike layer. `CARD_POOL` (20 defs: `id/name/description/max_stacks/on_pick/modifiers`), `Cards.owned` (stack counts), `Cards.modifiers` (flat table, **fully recomputed from `owned` on every pick** — declarative, not incrementally mutated). `Cards.get(key, default)` is the read API every other module uses. Two cards (Guardian Aura, Regeneration) tick continuously via `Cards.update` and "bank" their trigger — if the condition (shieldless / missing HP) isn't met when the timer completes, it holds at cap and fires the instant the condition becomes true, rather than needing exact timing.
- `src/debug.lua` — F1-toggle overlay + hotkeys; reads `Cards.modifiers`/`Cards.owned` directly for the readout.

No assets/sprites/audio — everything is drawn procedurally. User explicitly doesn't want music.

### Color palette (avoid clashes when adding new entities)
Player = cyan `(0,1,0.85)` · Enemy = red `(1,0,0.2)` · ZigzagEnemy = red-orange `(1,0.4,0.05)` w/ dark red outline · Orb = yellow `(1,0.9,0.2)` · VoidOrb = purple `(0.7,0.2,1)` · Shield = blue `(0.3,0.65,1)` · default Projectile = pink `(1,0.2,0.6)`. Boss types: Sentinel = magenta/pink `(1,0.1,0.6)` · Homing = emerald green `(0.15,0.9,0.45)` (also its projectiles) · Laser = amber `(1,0.55,0.05)` body, hot white-yellow beam · Splitter = chartreuse `(0.75,1,0.2)` · Turret = deep indigo-blue `(0.15,0.35,0.95)`. White/silver was tried for zigzag and explicitly set aside for a *future* power-up — don't reuse it for a hazard.

Iterated through several bugs after initial ship: a free card offered at game start (wave-counter off-by-one), perks not resetting between runs (`Player.reset()` never restored `max_lives`, so Vitality/Glass Cannon picks leaked across deaths), trigger moved from "every wave" to "every boss" per feedback, WASD card selection added to match the gamepad cursor flow, and a fractional-score bug from Glass Cannon's 1.5x multiplier (score is now rounded on every `increase_score` call).
13. **Five boss types** — converted `src/boss.lua` from a singleton to a small multi-instance array (needed for Splitter's clones) and added a `BOSS_TYPES` registry so Sentinel/Homing/Laser/Splitter/Turret share enter/exit/patrol/collision/draw code and only differ in config + a `fire` function. Cycle in a fixed sequence per `main.lua`'s `BOSS_SEQUENCE`. Added `Projectile`'s `homing` flag (steering-toward-player) for the Homing type, and a self-contained beam sub-system in `boss.lua` for the Laser type.
14. **Boss-type playtest fixes, round 1** (same session as #13, after the user tried it): homing projectiles had no lifetime and would chase the player forever even after the boss left — gave them a 6s expiry. Laser was originally a fixed-pivot rotating ray, which left the area near the boss permanently safe and the far arena permanently threatened — reworked into a full-arena-width horizontal band at a randomized row each cycle, plus one straight (non-homing) aimed shot per cycle. Turret was fully stationary — now orbits circularly around a fixed arena point, and its ring-burst rotates its angle offset a bit more each shot for a spiral pattern. Splitter's shot counts increased (3→6 original, 2→4 clones). Also added **dash invincibility**: `Player.is_dashing` now short-circuits `take_damage` to `"dodged"`, making the Quick Dash/Long Dash cards meaningfully defensive.
15. **Boss-type playtest fixes, round 2**: dash invincibility upgraded from "no damage" to true phase-through — every hazard's collision check now skips outright while dashing (no FX/removal either), not just the damage step; deliberately scoped to hazards only, Orb/VoidOrb pickups stay collectible while dashing since that's beneficial. Homing projectiles now spawn a small green burst FX when their lifetime runs out instead of silently vanishing. The laser's fixed-row band was still static during its firing window — it now slides between two randomized rows over the firing duration, and its aimed projectile shot was moved onto its own independent ~1s timer instead of firing only once per beam cycle, so it shoots noticeably more often. The turret's circular orbit had a one-time "zip" at encounter start (enter-phase landed it at the generic hover point, then hover's orbit formula instantly jumped it to the orbit's own starting position) — fixed by making both the spawn position and the enter-phase target match the orbit formula's angle-0 point for orbiter types, so there's no discontinuity. Also swapped `math.atan2` for a hand-written `atan2` built on single-arg `math.atan`, since `atan2` is removed in standard Lua 5.3+ (still fine on LÖVE's LuaJIT, but this removes the ambiguity for good).
16. **Boss-type playtest fixes, round 3**: the laser's row-slide from round 2 still only covered a small random distance — reworked into a genuine edge-to-edge sweep across the *whole* screen, randomly horizontal (top↔bottom) or vertical (left↔right), each direction equally likely, via `laser_axis` + the two screen edges as start/end. Turret's ring burst now fires twice per volley (~0.18s apart, second ring offset by half the angular spacing to interleave into the first's gaps) via a new generic `pending_second_burst`/`fire_second` mechanism on `Boss`, added specifically for this but reusable by any future type.
17. **Boss-type playtest fixes, round 4**: laser's shared `ENCOUNTER_DURATION` time budget didn't line up with its own beam-cycle length, so it could leave mid-telegraph or cut its last sweep off partway through — replaced with a shot-count exit (`laser_sweep_count >= LASER_MAX_SWEEPS`, set to 4) so it always plays exactly 4 full sweeps before leaving, no more, no fewer. Dropped the telegraph's second (end-position) indicator line — redundant now that every sweep spans a full screen edge to the opposite edge, it was just visual noise. Slowed the sweep down slightly (`LASER_FIRE_DURATION` 2.2s → 2.8s for the same full-screen distance).
18. **Boss-type playtest fixes, round 5**: homing shots could still be alive (mid-flight within their 6s lifetime) when the Homing boss itself left, so its threat could outlive it — added `Projectile.clear_homing()` (explosion-clears every active homing shot) plus a new generic `on_type_exit(type_id)` callback on `Boss`, fired once when any instance's phase flips to `"exit"`; `main.lua` wires it to call `clear_homing()` specifically when `type_id == "homing"`.
